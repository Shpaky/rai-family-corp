This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

# Правила проекта

## Тип сайта

Корпоративный B2B-сайт Rai Family Corp LLP с каталогом продукции (направлений). Не визитка,
не лендинг, не хаб со ссылками на отдельные сайты направлений и не интернет-магазин: корзины
и цен нет, розница живёт на therusstore.com. В текстах, комментариях и коммитах называть его
«сайт», разделы - «главная», «каталог», «страница направления».

## Стек

Astro 7 (Node >= 22.12), TypeScript strict, Tailwind 4 (`@tailwindcss/vite`).
Статическая сборка, клиентских фреймворков нет.
Никаких новых зависимостей без явного согласования. Утверждённый набор
dev-зависимостей — см. `package.json` (astro, sitemap, check, sharp,
tailwind, eslint/prettier с astro-плагинами, playwright + axe, lhci).

## Жёсткие ограничения

- Бюджет JS: <= 50 КБ на страницу (`npm run check:budget`)
- Lighthouse: Perf/A11y/BP >= 95, SEO = 100 (`npm run lighthouse`)
- Только токены из `@theme` в `src/styles/global.css`. Произвольные значения
  (`text-[13px]`, `bg-[#a3a3a3]`, hex в разметке/SVG) запрещены — `npm run lint:tokens`.
  В инлайн-SVG использовать `currentColor` и классы.
- Ссылки и ассеты учитывают `base` (`import.meta.env.BASE_URL`). Адрес и base
  задаются через env `SITE_URL` / `BASE_PATH` (см. `.env.example`); по умолчанию
  GitHub Pages `https://shpaky.github.io/rai-family-corp/`. После MVP хостинг
  сменится — в коде адрес не хардкодить. Для ссылок между страницами использовать
  `href(locale, path)` из `src/i18n/utils.ts`.
- Семантический HTML. Каждая интерактивная сущность доступна с клавиатуры.
  Компилятор Astro 7 строгий: все не-void теги закрываются.
- Все анимации отключаются при prefers-reduced-motion
- Изображения только через `<Image />`/`<Picture />` из astro:assets, avif/webp. У `<img>` и `<Picture>`
  с `aspect-ratio` (`aspect-4/5` и т. п.) нет фиксированной высоты: высота только от пропорции и ширины,
  фактический размер в `dist` проверяется замером (Playwright), а не атрибутами `width`/`height`.
  Фото павильона лежат в `src/assets/pavilion/`, подписи и alt — в `ui.ts` (`pavilion.photos`).
  Сырые файлы от заказчика — в `photos/` (в .gitignore), в ассеты копируются с понятными именами.

## Контент и i18n

- Локали: `en` (основная, без префикса), `ru` (`/ru/`). Хинди убран 2026-09-14 по решению
  заказчика. Страницы —
  через `src/pages/[...locale]/…` и `localePaths()`; hreflang/canonical даёт `Seo.astro`.
- Правило локалей: основной читатель EN - индийская сторона (дистрибьюторы, ритейл, госструктуры и
  институты развития, покупатели), основной читатель RU - российский производитель. Во всех разделах и
  на всех страницах порядок секций, карточек, аудиторий и ссылок ставит аудиторию локали первой, тексты
  обращаются к ней прямо, вторая аудитория идёт второй и не исчезает (`HOME_SECTIONS`, `AUDIENCE_ORDER`,
  `ABOUT_B2B_AUDIENCES` в `src/data/site.ts`).
- В текстах только дефисы: длинных тире (`—`, `–`) нет нигде в `src`, включая JSON направлений и
  заголовки страниц (`grep -rn "—" src` пуст).
- Все тексты — в `src/i18n/ui.ts` (EN источник, RU перевод). В разметке строк нет. Исключение - услуги
  (`src/data/services.ts`) и структурные тексты страницы «Производителям» (`src/data/manufacturers.ts`).
- Направления (продукты) — content collection `src/content/directions/*.json`
  (схема в `src/content.config.ts`), категории — `src/content/categories/*.json`.
  Отдельных сайтов у направлений нет: вся фактура живёт на странице
  `/directions/<slug>/`; каталог `/directions/`, категория `/directions/<category>/`
  (один маршрут `[slug].astro`, slug направления не должен совпадать с slug категории).
  Новое направление = папка в `./directions` (вне репозитория, `npm run check:directions`),
  JSON с обязательной `category` из коллекции и документы в `public/docs/<slug>/`.
  Документы: имена латиницей без пробелов, язык документа в `label` (`(EN)`, `(RU)`, `(EN/RU)`);
  английская и русская версии одного документа публикуются рядом как две записи `documents[]` с
  пометками языка, английская первой; тип из схемы (`tds`, `sds`, `certificate`, `test`, `reference` — референс-лист объектов, `authorization`,
  `leaflet`, `catalogue`, `presentation`),
  черновики, видео и смежные материалы не публикуются, файл не больше 3 МБ и папка направления
  не больше 15 МБ (тяжёлые PDF сжимать Ghostscript); PDF там не игнорируются благодаря
  `!public/docs/**/*.pdf` в `.gitignore`. Цифры на странице только из документов производителя,
  расхождения между документами не публикуются, а записываются в `TODO.md` как вопрос производителю.
  Цены на сайте не публикуются ни в каком виде: ни в текстах, ни в характеристиках, ни в документах;
  `howToBuy.priceNote` содержит только формулировку «по запросу» и перечень того, что указать в запросе
  (`npm run check:content`, входит в `lint`).
  В корне JSON только нетекстовые данные, всё читаемое — в `i18n.<locale>`.
  Поле `audiences` зарезервировано и нигде не выводится: все направления сайта B2B, розница
  живёт на therusstore.com. В каталоге фильтры — категория (ссылки) и наличие (чекбоксы).
  Карточка направления `DirectionCard.astro`: в ленте на главной `variant="compact"` (без обложки,
  бренда, описания и логистики; заголовок целиком, микроцифры столбиком по одной на строку), в
  каталоге и «Похожих» — `full`; обложка только при `image`, заглушек нет. Ничего не обрезается
  визуально: `title` до 70 символов и сам называет бренд и тип продукта, `keyFigures` до двух строк
  по 32 символа, длинные формулировки — в `facts`; `npm run check:cards` держит высоту compact-карточки.
  Категории: `construction`, `equipment`, `electronics`, `health`, `industrial-chemicals`, `agro`. Направления о
  здоровье (`health`): без медицинских и терапевтических утверждений, показаний и клинических ситуаций; на странице

  на главной выключен флагом `SHOW_CATEGORY_TILES` в `src/data/site.ts`; включать, когда опубликованных
  направлений больше 12 и лента показывает не весь портфель. Плитки берут фон, противоположный фону секции (`tone`). Лента на главной, фильтры каталога и
  инлайн-скрипт раскрывающихся блоков на `/manufacturers/` — единственный клиентский JS на сайте (до 4 КБ, без библиотек).
- Бренд (вариант H «Олива и охра», с 2026-09-26; до этого вариант F с терракотой с 2026-09-20): свой стиль
  на тёплой палитре — олива `dark` #4D5A2C (тёмные поверхности), жжёная охра `primary` #9D5A10 (кнопки,

  `gold` #D4B06A только для знака на тёмном, `gold-deep` #8A6B35 для знака на светлом, номеров этапов и
  фокуса, `gold-text` #E6CC95 для мелких подписей на оливе. Красный и синий на странице только внутри

## Люди

- Руководство — коллекция `people` (`src/content/people/*.json`, фото в `src/content/people/photos/<slug>.jpg`).
  Новый человек = JSON плюс фото; фото не кадрировать и не ретушировать, кроп через CSS (`object-cover`),
  форматы и размеры через `astro:assets`. Секция «О компании» выводит группу `leadership` по `order`
  (`PersonCard.astro`: две карточки в ряд, портрет 4:5 по ширине колонки, имя, должность; без ссылок и биографий),
  под карточками кнопка «Подробнее о компании» на `/about/`. `bioLead` (вводная строка) и `bio` (пункты
  списка) выводятся только на `/about/` (`PersonProfile.astro`); факты биографий только утверждённые.
  Об учредителях на сайте только фраза в тексте секции и вводная строка руководства на `/about/`, имена не публикуются.

## Страница «О компании»

- `/about/` и `/ru/about/` (`src/pages/[...locale]/about.astro`), пункт меню «About» / «О компании» в шапке
  и подвале ведёт на неё, а не на якорь `#about` (`SECTION_PAGES` в `src/data/site.ts`; там же `directions`
  и `services` → `manufacturers/`).
  Активный пункт меню на своей странице получает `aria-current="page"` и `text-primary`.
- Пять секций в этом порядке: 1) две модели бизнеса B2B и B2C в шапке страницы (`bg-surface`, две
  карточки на общих рядах сетки `grid-rows-subgrid`, порядок аудиторий и ссылок B2B по локали из
  `ABOUT_B2B_AUDIENCES`, The Rus Store - «наш интернет-магазин», ссылка внешняя); 2) руководство с
  описанием опыта (`PersonProfile.astro`); 3) статус и знак; 4) реквизиты; 5) контакты. Фоны секций 2-4
  чередуются по позиции (белый, `surface`, белый), контакты - единственная тёмная поверхность.
  Хронологии, ряда цифр, плиток «что мы делаем» и призывов «с чего начать» на странице нет.
- Секции 3 и 5 переиспользуют существующие компоненты без новых версий и текстов: `StatusLockup`
  в варианте `footer` со строками `footer.operator` и `footer.madeInRussia`, `sections/Contacts.astro`
  как на главной, но с `id={null}` (меню «Контакты» ведёт на `/#contacts`).
- Портреты на `/about/` не привязаны к главной: ступени по шкале Tailwind `w-48` (от 640) / `w-64`
  (от 1024) / `w-80` (от 1280), до 640 сетка `grid-cols-5` с портретом `col-span-2`; пропорция 4:5
  через `aspect-4/5`, высота не задаётся. Нижняя граница 192 px, верхняя 320 px (исходники 320 / 480 / 640).
- Реквизиты берутся из `src/data/company.ts` (`legalName`, `llpin`, `registeredOn`, `registrar`,
  `gstin`, `iec`, `jurisdiction`, `registeredOffice`, `proofLinks`), подписи в `ui.ts` (`aboutPage.details`).
  Публикуются только подтверждённые документами значения; часы работы не выводятся и не заменяются заглушками.
  Документы компании лежат в `public/docs/company/` (`company.documents`, кнопки под реквизитами по правилу
  документов направлений). GST-свидетельство публикуется без приложения B (назначенные партнёры с фото):
  страницы 1-2, свидетельство и приложение A с местами ведения бизнеса. Сертификат IEC с именем подписанта
  опубликован как есть по решению заказчика 2026-09-26; на страницы сайта имена не переносить.
- JSON-LD страницы: `AboutPage` с `mainEntity` типа `Organization` и `relatedLink` из `company.proofLinks`;
  `Organization` в `Seo.astro` берёт `legalName`, `foundingDate` и адрес оттуда же.
- Внешние ссылки (магазин, страница программы РЭЦ): новая вкладка, `rel="noopener"`, стрелка, sr-only
  пометка `external.newTab`; языковая пометка рядом со ссылкой («на английском» в RU у магазина,
  «in Russian» в EN у страницы РЭЦ).

## Услуги и страница «Производителям»

- Услуги описываются один раз, в `src/data/services.ts`: восемь групп (`id` «01»-«08», `slug`, `title`,
  `brief`, `items[{ text, headline }]`), 36 услуг, обе локали, состав проверяется при импорте. Группы и
  строка-резюме выводятся на главной, полный перечень - на странице `/manufacturers/`, шаги маршрута
  ссылаются на группы (`serviceGroups` → `#services-<slug>`). Больше нигде услуги не перечисляются, в
  `ui.ts` их нет. `headline` (три заглавные услуги группы) хранится на будущее и нигде не выводится.
- Секция «Услуги» на главной (`sections/Services.astro`): eyebrow и H2 прежние, восемь компактных
  карточек (номер, название, одна строка `brief`; без списков, подзаголовков и ссылок), одна колонка
  до `md`, две от `md`, четыре от `xl`, под сеткой кнопка `services.more` на страницу. Высота секции на
  360 не больше прежней секции с четырьмя этапами (2099 px EN, 2235 px RU).
- `/manufacturers/` и `/ru/manufacturers/` (`src/pages/[...locale]/manufacturers.astro`, секции в
  `src/components/manufacturers/`): третья пара «тизер на главной плюс страница». Основной читатель -
  российский производитель, EN - перевод для hreflang и экспортных менеджеров. Пункт меню секции
  `services` называется «For manufacturers» / «Производителям» (`nav.manufacturers`, соответствие секции
  и подписи - `SECTION_NAV` в `src/data/site.ts`) и ведёт на страницу (`SECTION_PAGES`); позиция в меню
  прежняя. Тем же текстом `services.more` ведут на страницу ссылка в блоке B2B на `/about/` и ссылка в
  карточке «Российские производители» секции аудиторий.

  под ним в той же секции четыре рыночные цифры со строкой «источник, год» и фраза о среднем классе;
  отдельной секции «рынок» нет, абзаца-оглавления нет); маршрут до полки (шесть шагов со
  строкой «Услуги:»); перечень услуг (восемь `<details>` с якорями `services-<slug>`); что нужно от
  производителя (общий список и шесть категорий, slug как у категорий каталога); модели сотрудничества
  (у карточки «Резидентство в павильоне» ссылка «О павильоне» на `/#pavilion` локали, поле `link` элемента
  `models.items[]`, у остальных `null`); чего мы не делаем; вопросы и ответы; «С чего начать» - единственная
  тёмная поверхность. Павильон на странице упоминается там, где он относится к делу: шаг 6, карточка
  модели, FAQ. Порядок - `MANUFACTURERS_SECTIONS`, фон по позиции среди отрендеренных секций (белый,
  `surface`, ...); секция контактов главной на странице не выводится.
- Данные страницы - `src/data/manufacturers.ts` (типизированный объект на локаль), короткие строки
  интерфейса - `ui.ts` (`manufacturersPage.*`); в компонентах текстов нет. Пустое поле - блок не

  `md` блоки шагов и списка открыты, их summary скрыты, первый вопрос открыт; категории и группы перечня
  свёрнуты на всех ширинах (группу открывает ссылка «Услуги:» из шага). Подписи строк шага: до `md` в строку перед текстом, от `md` над текстом, от `lg` колонкой
  104 px слева. Один инлайн-скрипт шаблона (около 0,5 КБ, без зависимостей) по
  `matchMedia('(max-width: 767px)')` снимает или ставит `open` у `details[data-collapse="mobile"]` при
  загрузке и смене медиазапроса и открывает группу, на которую ведёт ссылка `#services-<slug>`; без JS
  всё остаётся открытым. Разметку под ширины не дублировать, другого клиентского кода на странице нет.
- Статус оператора показывается на сайте в трёх местах: hero главной, блок статуса на `/about/` (полная
  версия с подтверждениями) и подвал каждой страницы. На остальных страницах, в том числе на
  `/manufacturers/`, статус отдельной секцией не выводится; павильон как место живёт в секции «Павильон»
  главной и на будущей странице `/pavilion/`.
- Переиспользование без новых версий: `hero.pavilionLink` (подпись ссылки в карточке модели), хелперы
  `whatsappUrl` / `whatsappsFor` и mailto с темой, как у страниц направлений (старт). Кнопки на оливе -
  на светлых плашках (`secondary`, `ghost`), охры на оливе нет.
- Никого не персонализировать: ни имён, ни должностей, ни «ответственного за производителей»; контакт
  общий (почта и WhatsApp компании). На странице нет цен, сроков в днях и месяцах, числа резидентов,
  «бесплатно», тендеров и госзакупок; не пишем, что компания - авторизованный индийский представитель,
  что склады собственные, что участие в павильоне необязательно, города складов не называем (всё это
  ждёт подтверждения, см. `TODO.md`).
- JSON-LD страницы: `WebPage` (`isPartOf` → `WebSite`, `about` → `Organization`), `BreadcrumbList`,
  `FAQPage` из вопросов с ответом; `HowTo` и `Service` не добавлять.

## Главная

- Порядок секций главной и карточек «С кем мы работаем» задаётся только в `src/data/site.ts`
  (`HOME_SECTIONS`, `AUDIENCE_ORDER`) и различается по локалям: секция аудиторий —
  оглавление трёх следующих секций, первой стоит аудитория основного читателя локали.
  Hero всегда первый, `contacts` всегда последняя; конфиг валидируется при импорте.
- Кнопки hero задаются по локали в `HERO_ACTIONS` (`src/data/site.ts`), не в компоненте: две кнопки,
  первая (`primary`) обращена к основному читателю локали (RU «Вывести продукт в Индию» на
  `/ru/manufacturers/`, EN «Explore directions» на `#directions`), вторая (`secondary`) «Связаться» /
  «Contact us» на `#contacts` в обеих; третьей кнопки нет. Подписи - `hero.contact`, `hero.directions`,
  `hero.manufacturers` в `ui.ts` (все три ключа в обеих локалях, выводятся по `HERO_ACTIONS`). Тексты
  hero (eyebrow, H1, лид, карточка) одинаковы по смыслу в обеих локалях и меняются отдельным решением.
- Меню шапки и подвала строится из того же конфига (`navItems()` в `src/i18n/utils.ts`):
  `directions` ведёт на `/directions/`, `services` («Производителям», подпись из `SECTION_NAV`) на
  `/manufacturers/`, `about` на `/about/` (`SECTION_PAGES`), остальные — на якоря главной; `audiences`
  в меню нет.
- Новая секция главной = компонент с пропами `locale` и `tone?: SectionTone`, ключ в
  `HomeSectionKey`, запись в обе локали, при необходимости подпись в `nav.*`.
- Фон секции — свойство позиции, его вычисляет `index.astro`: hero белый, дальше бумага
  (`surface`) и белый через одну, Contacts тёмная. В компонентах секций корневой фон только через
  проп `tone`; жёсткий `bg-*` на корне секции запрещён. Карточки на светлых фонах — тень плюс
  `border border-line`. Новая секция (в том числе «Новости») встаёт в ряд, фоны ниже переворачиваются
  сами. Тёмных поверхностей на главной две: hero-карточка и Contacts. `npm run check:home`
  (входит в `lint`, после `build`) сверяет порядок секций, чередование фонов, меню и первую карточку аудиторий.

## Процесс

- Одна секция главной или страница = один коммит (`feat(<section>): ...`), push после коммита.
- Перед коммитом: `npm run build && npm run lint && npm run test:a11y`
- После каждой секции сделать скриншоты на 360/768/1280 (`npm run shots`) и показать.
- `npm run check:budget` и `npm run lighthouse` — перед пушем крупных секций и перед релизом.
- Astro 7 `preview` уходит в фон, когда видит агентское окружение; тестовые скрипты
  запускают его с `ASTRO_PREVIEW_BACKGROUND=1 … --ignore-lock`, чтобы он остался на переднем плане.
